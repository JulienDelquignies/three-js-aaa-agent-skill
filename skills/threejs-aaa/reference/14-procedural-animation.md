# Procedural Animation

Motion generated by math, not baked clips: springs, damping, IK, look-at/aim, secondary motion,
foot IK. Layer these ON TOP of Mixamo clips (`05-characters-mixamo.md`) for responsiveness and
ground adaptation. The starter ships tested, dependency-free implementations in
`assets/starter/src/engine/procedural.js` (+ `vecmath.js`); `scripts/verify-interaction.mjs
--selftest` proves the math.

## Frame-rate-independent damping

Never lerp by a fixed fraction per frame — it's frame-rate dependent. Use exponential damping:

```js
import { damp, dampVec3 } from './engine/procedural.js';
// higher lambda = snappier; identical result at 30fps and 240fps
camera.position.fromArray(dampVec3(camera.position.toArray(), targetPos, 6, dt));
value = damp(value, target, 10, dt);
```

`damp(current, target, lambda, dt) = target + (current-target)·e^(-lambda·dt)`.

## Springs

Critically-damped springs give organic overshoot-free (or bouncy) motion for cameras, aim, recoil,
UI, and "juice":

```js
import { Spring, SpringVec3 } from './engine/procedural.js';
const aim = new SpringVec3({ stiffness: 180, damping: 26 });
aim.setTarget(targetPos);           // each frame:
crosshair.position.fromArray(aim.update(dt));
```

Tune: higher `stiffness` = faster, higher `damping` = less bounce. `damping ≈ 2·√stiffness` is
critical (no overshoot); lower damping = springy.

## Two-bone IK (arms/legs)

Analytic IK for a limb — place the hand/foot exactly on a target, solve the elbow/knee from a pole
hint. The workhorse for reaching, foot planting, weapon holding.

```js
import { twoBoneIK } from './engine/procedural.js';
// root = shoulder world pos, target = hand goal, lenA = upper arm, lenB = forearm,
// poleDir = which way the elbow points (e.g. behind/below)
const { root, mid, end, reachable } = twoBoneIK(shoulderPos, handTarget, upperLen, foreLen, poleDir);
// reachable=false → target beyond arm length; limb points at it fully extended.
```

It returns joint world positions (bone lengths are exactly preserved). Convert to bone rotations
by aiming each bone at the next joint (see [Driving THREE bones](#driving-three-bones)).

## Look-at / aim with rate limiting

Snap-free turning: rotate a forward vector toward a desired direction at a max angular rate.

```js
import { turnToward } from './engine/procedural.js';
import { quatLookRotation } from './engine/vecmath.js';
forward = turnToward(forward, desiredForward, /*rad/s*/ 6, dt);
head.quaternion.fromArray(quatLookRotation(forward, [0,1,0])); // orients local +Z along forward
```

Use for head/eye look-at, turret aiming, character heading. Combine additively with a Mixamo idle
so the look layers on top.

## Secondary motion & idle

- **Idle/breathing/sway**: `idleNoise(t, {freq, amp, octaves, seed})` — deterministic layered sine
  for chest rise, weapon sway, ambient bob. Add small offsets to bone rotations/positions.
- **Jiggle/spring bones**: run a `SpringVec3` whose target is a bone's animated position; the lag
  produces cloth/hair/antenna follow-through. (For full VRM spring bones, `@pixiv/three-vrm`.)

## Foot IK on terrain

Plant feet on uneven ground so they don't float or clip:

1. Raycast down from each foot bone (use `three-mesh-bvh` on the terrain — `08-scattering-instancing.md`).
2. If the hit is above the animated foot, raise the foot to the hit point (and lift the hips by the
   max correction so legs don't over-stretch).
3. Solve the leg with `twoBoneIK(hipPos, footTarget, thighLen, shinLen, kneePole)`.
4. Align the foot to the ground normal (`quatFromTo(footUp, hitNormal)`).

Do this after `mixer.update(dt)` each frame. Validate the result with `checkGroundContact`
(`15-interaction-alignment.md`).

**Moving characters that must not slide** → see `21-locomotion-no-footskate.md`: `matchCadence()` ties
clip phase to distance travelled and `FootLockIK` (built on the `twoBoneIK` above) pins the planted foot.
That's the dedicated fix for foot-skate on a locomoting character; foot-IK-on-terrain here is about
height/normal on uneven ground.

## Driving THREE bones

The math modules use arrays; bridge to Three.js:

```js
// world position of a bone
const p = new THREE.Vector3(); boneA.getWorldPosition(p);
const solved = twoBoneIK(p.toArray(), target.toArray(), a, b, pole);
// aim a bone at the next joint: build a quaternion from the bone's rest direction to the new one
const dir = new THREE.Vector3().fromArray(solved.mid).sub(p).normalize();
boneA.quaternion.copy(/* rest-to-dir quaternion, then convert world→local via parent inverse */);
```

Remember bones are in parent-local space: convert your world-space target rotation to local with
`bone.parent.getWorldQuaternion(q).invert().multiply(worldQuat)`.

## Multi-bone IK & physics

- **CCDIKSolver** (`three/addons/animation/CCDIKSolver.js`) — iterative IK for chains >2 bones
  (spine, tail, tentacles). Configure `iks` and call `solver.update()` after `mixer.update()`.
  See `05-characters-mixamo.md`.
- **Physics-driven** — ragdolls, rope, cloth via Rapier joints; blend physics poses with animated
  ones by weight for hit reactions.
